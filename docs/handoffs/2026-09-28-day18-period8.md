## 원본 계약과 실제 결과

- source table: `village.game_gameevent` (`GameEvent._meta.db_table == game_gameevent`).
- format: UTF-8 JSON Lines, 한 줄에 JSON object 하나.
- fields: `schema_version,event_id,event_type,player_id,room_id,event_time,payload`.
- 범위: since·until 없는 명령 실행 시점의 전체 DB 조회.
- 5,968행, 고유 `event_id` 5,968개, 중복 0개, 잘못된 필드 행 0개.
- 첫 시각 `2026-09-11T08:07:35.823171+00:00`, 마지막 시각 `2026-09-28T06:32:46.103324+00:00`.
- DB export에는 Kafka partition·offset을 만들지 않았다.

현재 Delta 기반 `game-summary.json`은 5,707건으로 DB export와 생성 시각·원천 경계가 다르다. 두 count를 같은 snapshot처럼 보지 않으며, 원본의 `event_id`를 보존한 뒤 같은 범위가 필요할 때 Kafka→Delta 처리와 요약을 다시 완료한다.

## 책임 경계

- export 명령은 DB를 읽고 파일을 교체할 뿐 publisher, Kafka, Spark와 게임 명령을 실행하지 않는다.
- `since`는 포함, `until`은 제외이며 timezone 포함 ISO 시각만 허용한다.
- iterator chunk 1,000으로 읽어 전체 QuerySet을 list에 올리지 않는다.
- 임시 파일을 완성한 뒤 최종 경로로 교체한다.
- 비밀번호, Cookie, session, CSRF와 DB 비밀값은 인계 파일에 기록하지 않았다.

## 다음 시작 순서

NiFi가 필요 없는 기본 수업 프로필은 프로젝트 루트에서 시작한다.

```powershell
cd C:\MLO01-01\Chapter3\Game-server
.\start-dev.cmd -Profile without-nifi
```

그 다음 각 별도 PowerShell에서 서버 폴더로 이동해 ASGI 서버, publisher, Python 변환기와 Delta stream을 실행한다.

```powershell
cd C:\MLO01-01\Chapter3\Game-server\server
.\.venv\Scripts\python.exe manage.py runserver --noreload 127.0.0.1:8000
.\.venv\Scripts\python.exe manage.py publish_game_events
.\.venv\Scripts\python.exe manage.py transform_game_actions
.\.venv\Scripts\python.exe manage.py run_game_delta
```

원본을 다시 내보낼 때는 별도 PowerShell에서 실행한다.

```powershell
cd C:\MLO01-01\Chapter3\Game-server\server
.\.venv\Scripts\python.exe manage.py export_game_handoff --output ..\data\handoff\day18\game-events.jsonl
```

종료 시 새 게임 입력을 먼저 멈추고 publisher·변환기·Spark의 남은 처리와 lag를 확인한 뒤 각 터미널에서 정상 종료한다.
